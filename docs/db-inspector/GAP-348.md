# GAP-348 — SELECT-only database inspector

Native inspector scaffold in `@revdev/db-inspector`. It runs inside RevDev. It does not embed or proxy an external UI host (no Adminer, pgweb, psql wrapper, or hosted SQL studio).

Every accepted query is one `SELECT` or one `WITH ... SELECT`. Each query writes one audit receipt. The SQL guard rejects `INSERT`, `UPDATE`, `DELETE`, DDL, `SELECT ... INTO`, more than one statement, and comments that hide a write. Line comments are rejected because they hide the rest of the line.

The wrapper binds the row limit and the statement timeout as parameters (`LIMIT $1` and `set_config('statement_timeout', $1, true)`). It does not interpolate those numbers into SQL text. The steps run in one `BEGIN READ ONLY` transaction so the timeout applies to that query and does not stick on a later session.

## Blocked on the owner

Blocked on a SELECT-only role on the **current** production database. No new Neon compute (no new project, branch endpoint, or read replica). Joshua creates the role and vaults the URL. Do not put the password or the URL in chat, code, tests, or docs.

## Environment

| | |
| --- | --- |
| Env var | `DATABASE_URL_READONLY` |
| Vault path | `revealui/prod/db/postgres-url-readonly` |

If `DATABASE_URL_READONLY` is missing or blank, the inspector throws `ReadonlyDatabaseUrlError` and does not connect. There is no fallback URL and no default database.

## OWNER steps

1. Stay on the current production Neon database. Do not create a compute.
2. Create a login role that can `SELECT` and cannot `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, or run DDL. Set the password out of band. Never commit it and never paste it into chat.
3. Vault that role's connection URL at `revealui/prod/db/postgres-url-readonly`. The URL uses the existing production host. Do not invent a host.
4. Export the vaulted value to the inspector process as `DATABASE_URL_READONLY` only. Do not reuse the read-write `DATABASE_URL` / `POSTGRES_URL`.

Run the role SQL on the current production database. Replace `<current_production_database>` with the database that already exists. Do not create one.

```sql
CREATE ROLE revealui_inspector LOGIN;

GRANT CONNECT ON DATABASE <current_production_database> TO revealui_inspector;
GRANT USAGE ON SCHEMA public TO revealui_inspector;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO revealui_inspector;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO revealui_inspector;

REVOKE INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES, TRIGGER
  ON ALL TABLES IN SCHEMA public FROM revealui_inspector;
```

After `CREATE ROLE`, set the password out of band (Neon console or a local client). Put only the finished URL in the vault path above.

## Limits

| Parameter | Allowed |
| --- | --- |
| `rowLimit` | integer 1 through 1000 |
| `statementTimeoutMs` | integer 1 through 15000 |

`0` is rejected. In PostgreSQL a statement timeout of `0` disables the timeout.

## Tests

Unit tests cover the guard and the missing-env error. They use a fake executor. They do not open a database and they do not contain a password or a connection string.
